03 The Minimal-Change Constitution ADD TO SOUL
⚖ Laws Every Agent Must Internalize
L-01
Working features are sacred. If a feature works today, no agent may touch its code unless that specific feature is in the active track's scope. Any accidental modification to a working feature is an automatic SIT failure requiring a full revert.
L-02
Add, don't rewrite. New functionality must be added as new functions, new endpoints, new components — not by rewriting existing ones. If a fix requires changing an existing function, that change must be the minimum possible delta.
L-03
Every change must be commented. Any new line or modified line must have a comment beginning with // [TRACK-X] identifying which track added it. This enables precise rollback.
L-04
No speculative improvements. DEV Workers may not "clean up" or "optimize" code outside their track scope, even if the code looks bad. Scope creep disguised as refactoring breaks working features. Flag it to PM instead.
L-05
100% completion or nothing. A track is either fully done (all tasks complete, all KPIs green) or it isn't merged. Partial merges are prohibited. DEV Workers submit only when their entire track spec is satisfied.
L-06
Data lifecycle is inviolable. POST /upload and POST /restart must always delete runtime_data.json. Any agent modifying these endpoints must verify this lifecycle hook is preserved. Silent stale-data bugs are the worst class of failure.

06 100-Scenario UAT Protocol QA OWNED
🧪 Scenario Distribution
  • 30 scenarios: Happy path (standard use cases)
  • 25 scenarios: Edge cases (empty fields, max chars, special chars)
  • 20 scenarios: Regression (all features from prior phases still work)
  • 15 scenarios: Negative testing (invalid inputs, wrong formats)
  • 10 scenarios: Concurrency & state (upload new file mid-run, restart during execution)
📋 Defect Report Required Fields
  • Scenario ID (e.g., UAT-P1-047)
  • Steps to Reproduce (numbered, exact)
  • Expected Result
  • Actual Result
  • Severity: CRITICAL / HIGH / MEDIUM / LOW
  • Screenshot or terminal log evidence
  • Phase + Track reference (e.g., Phase 1, Track A)
✅ Zero-Defect Certificate Format

QA Lead must issue this exact statement to PM Agent upon 100% pass:


"Phase [N] UAT Complete. 100/100 scenarios passed. Zero unresolved defects. Zero regressions detected on prior phase features. Phase [N] is certified ready for PM sign-off and promotion to stable-web."

🔁 Defect Loop Trigger

If any defect exists, QA Lead issues this to PM Agent:


"Phase [N] UAT FAILED. [X] defects found. [Y] CRITICAL, [Z] HIGH. Full defect report attached. Loop Iteration [N]. Returning to DEV for remediation."


PM routes each defect to the DEV Worker that owns the relevant track.
